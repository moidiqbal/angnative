## 0. What this plan decides, and what it assumes

| # | Decision | Value used here | Source / note |
|---|---|---|---|
| D-1 | Backend | **Rust host is the only native backend.** No React Native, no Fabric, no Expo runtime. | User direction, 14 Nov. Replaces spec D1. |
| D-2 | Canonical identity | **AngNative**, npm scope `@angnative/*`, element prefix `na-` | The repo is `angnative`. Spec says `NativeAngular`/`@nativeangular/*`/`an-` — **must be reconciled** (P0.1). Prefix `na-` follows spec D9. |
| D-3 | Licence | **MIT** | Spec §14 + §15. Repo metadata says "MIT OR Apache-2.0" — fix it. |
| D-4 | Layout owner | **Rust (taffy) lays out; the platform draws.** | Spec §5.6 CSS subset must be exact. If the platform lays out, "one codebase, every platform" is false. |
| D-5 | JS engine | **Engine-neutral trait; QuickJS-ng (rquickjs) default; JavaScriptCore on Apple platforms where available.** | Spec D5 + §11.1 "iOS: 0 KB (JavaScriptCore is in the OS image)". Dropping RN removes Hermes from Apple; JSC keeps that 0 KB. |
| D-6 | Web | **Web does not use the native renderer.** It uses Angular's own DOM renderer. | Free lane — see §3.6. This is how RN's web story works too (`react-native-web` is a DOM renderer). |
| D-7 | Scope order | **Android → iOS → macOS → watchOS/tvOS → Windows/Linux** | Android-first per every task list; watch/tv last because they are the only platforms RN cannot reach. |

**Scope reality, stated plainly.** Spec §14 assumes a team of 2–4 and says plainly: *"If the team is
one Angular engineer, M1 alone is the realistic ceiling and M3 is a multi-year proposition."* This
plan targets **one engineer**. Therefore: **Phase 1 and Phase 2 are the whole near-term game**;
Phase 3 is one platform at a time; the breadth (web + mobile + desktop + watch/TV) is a *direction*,
not a quarter. Nothing in this plan requires more than one machine and one person to complete a
phase end to end.

## 1. Non-negotiables (carried from the spec, with the corrections this plan makes)

1. Angular pinned **exactly 22.2.5**; TypeScript **exactly 6.0.3**; Node **>= 22.12**; pnpm **10.34.9**.
2. **AOT only.** `@angular/compiler` never reaches a runtime, test or device bundle. The device
   never runs a compiler — not even in dev (spec D7).
3. **Zoneless.** Zero `zone.js`, ever.
4. Angular private (`ɵ`) API confined to **exactly one file**: `packages/platform/src/angular-internals.ts`.
5. **Unknown property writes must throw**, not no-op (spec §5.3). This is the rule that converts a
   silent device failure into a loud test failure.
6. **Every gate is mutation-tested**: inject the original defect, confirm the gate fails with that
   defect's exact numbers (spec §10.7).
7. npm scope `@angnative/*` — never `@angular/*`, never `ng-native` (taken upstream).
8. Size budget: **<= 60 KB gzip** hello-world JS, **<= 250 KB** typical app, **0 B** `@angular/compiler`
   and `zone.js`. Rust core **<= 1 MB per platform, measured** (spec D8).
9. Dev loop: **<= 200 ms** per changed component, **<= 500 ms** inner loop end to end.
10. Perf gates are measured **against an RN baseline on the same device** (spec §11.2) — see R-4.

## 2. Architecture — one diagram, three languages, one boundary

```
┌──────────────────────────────────────────────────────────────────────┐
│ APPLICATION (Angular)                                                │
│ components · signals · DI · @angular/router · Signal Forms          │
│ <na-view> <na-text> <na-list> <na-text-input> <na-pressable> …      │
└───────────────────────────┬──────────────────────────────────────────┘
                            │ Renderer2 / RendererFactory2 SPI
┌───────────────────────────▼──────────────────────────────────────────┐
│ TYPESCRIPT LAYER  (backend-agnostic — survives every backend choice)│
│ @angnative/contract   elements · style table · command protocol     │
│ @angnative/core       ElementRegistry · CapabilityRegistry · SPI    │
│ @angnative/platform   DOM-less Angular platform (bootstrap)         │
│ @angnative/testing    fake backend + THE SHARED CONFORMANCE SUITE   │
│ @angnative/router     native navigation · LocationStrategy          │
│ @angnative/cli        doctor · create · test · build · dev          │
└───────────────────────────┬──────────────────────────────────────────┘
              command protocol (JSON, versioned)  ← THE BOUNDARY
┌───────────────────────────▼──────────────────────────────────────────┐
│ RUST HOST  (the only native backend)                                │
│ angnative-host-core      element tree · command decode · diff/patch  │
│ angnative-host-layout    taffy layout · text-measure trait           │
│ angnative-host-view      view tree · ViewFactory trait · platform ops│
│ angnative-host-engine    engine-neutral trait · QuickJS-ng · JSC     │
│ angnative-host-ffi       C ABI for the platform shells (no TS here) │
│ angnative-services-core  capability resolver · offline-sync · crypto│
│                           · serialization · diagnostics (usable     │
│                           without Angular — spec §5.9)               │
└───────────────────────────┬──────────────────────────────────────────┘
                            │ FFI (C ABI / JNI / Swift)
┌───────────────────────────▼──────────────────────────────────────────┐
│ PLATFORM SHELLS (thin)                                               │
│ Android (Kotlin + android.view.View) · iOS (Swift + UIKit)          │
│ macOS (AppKit) · watchOS · tvOS · Windows · Linux                    │
└──────────────────────────────────────────────────────────────────────┘
```

**The boundary is the product.** Everything above it is TypeScript; everything below it is Rust and
platform code. The conformance suite is what keeps both sides honest.

**Web sits beside the native stack, not inside it.** A web build uses Angular's own
`@angular/platform-browser`. Same components, same services, same validators — different renderer.
That is how React Native does web too.

### 3.1 Phase 1 — TypeScript layer (backend-agnostic, survives everything) — **SV**

This phase is the foundation for the Rust host *and* the reason the Rust host is cheap. It is the
part of M1 that does not care which backend wins.

| ID | Task | Definition of done | Verification |
|---|---|---|---|
| T1 | `@angnative/contract` — 10 element contracts, the §5.6 CSS-subset style table, value parsers, and the **command protocol** (this is the TS↔Rust wire format) | Round-trip tests; every element kind has a contract | `pnpm vitest run packages/contract` |
| T2 | `createElementRenderer` — **one** renderer, written once, above an element-factory SPI. No per-platform forks. | Used by the fake backend *and* the Rust host | conformance suite green |
| T3 | **The shared conformance suite** — create / append / remove / prop / style semantics, view flattening, list recycling, capability degradation, error cases | Every backend passes it; the suite is the only place backend semantics are defined | `pnpm vitest run packages/contract/src/conformance.spec.ts` |
| T3a | **The 7 mutation "teeth" specs** — inject the original defect, assert the suite fails with that defect's exact numbers | The specs are committed, not just documented | each mutant ⇒ red |
| T4 | Fixture migration `an-` → `na-` + wire `createElementRenderer` into `bootstrapNativeAngular`; prove a real Angular 22.2.5 AOT app renders through it | The AOT artefact shows `inputs: {…}` + `consts: […]` and no `renderer.setProperty` | `pnpm run compile:fixtures && pnpm test` |
| T5 | Close the 7 "fix before M1" items from the M0 review: fake-node DOM fidelity (re-parent, non-member `removeChild`), `createNativeDocument` keeping text/comment payloads, multiple listeners per event, the `@angular/core/testing` guard, `exports` → `dist`, `provideNativeAngular` coverage, `backend.elements` → `ElementRegistry` | Each has a test that fails without the fix | the M0-review list, item by item |
| T6 | CLI — `doctor` / `create` / `test` / `build` / `dev`. `create` must not advertise commands that do not exist. | Every advertised command runs | clean-checkout test |
| T7 | Size budget CI — terser-class DCE to reach <= 60 KB gzip (measured baseline today: **90,438 B** gzip prod, `@angular/core` = 96.3% of payload). Gate blocks when the budget is exceeded, when the metafile is missing, or when the bundle contains `@angular/compiler` / `zone.js`. | `node scripts/check-size-budget.mjs` prints measured gzip size and exits 0 | budget is a gate, not a number to move |
| T8 | Dev server — incremental AOT, **<= 200 ms** per changed component, <= 500 ms inner loop. Dev bundles stay out of the production size gate. | Reproducible benchmark, multiple warm runs | benchmark artefact |
| T9 | Router — `@angnative/router`, native navigation stack, hardware back + swipe-back, deep links, guards/resolvers/lazy routes unchanged | `LocationStrategy` API verified against installed `@angular/common@22.2.5` | spec suite |

### 3.2 Phase 2 — The Rust host (sandbox-verifiable, no device needed) — **SV**

This is the new work. It is deliberately small and boring: a host that owns a tree, computes
layout, and emits platform operations.

| ID | Task | Definition of done |
|---|---|---|
| R1 | `angnative-host-core` — element tree, command decode (serde), retained-tree model, **diff/patch engine** (Fabric's model: a commit is a set of mutations, not a rebuild) | Unit tests; commands decode; diff emits minimal op set |
| R2 | `angnative-host-layout` — taffy 0.15 layout + a `TextMeasurer` trait; `NaiveMeasurer` for unit tests, platform measurer (CoreText / StaticLayout) behind the same trait | Layout tests against known flex/grid cases; text cache keyed `(text, font, available width)` |
| R3 | `angnative-host-view` — view tree + `ViewFactory` trait + platform op emission (`Create / SetFrame / SetProps / SetText / Append / Insert / Remove / Destroy`) | Ops are deterministic and ordered |
| R4 | **The Rust host passes the same conformance suite as the TS fake backend** — same JSON fixtures, two runners | One suite, two implementations, both green. **This is the keystone of the whole plan.** |
| R5 | `angnative-host-engine` — engine-neutral trait; QuickJS-ng (rquickjs) impl; JavaScriptCore impl for Apple; dev-mode inspector hook | The TS side never learns which engine is embedded (spec D5 / `nativeangular-js`) |
| R6 | `angnative-host-ffi` — C ABI for platform shells. No TypeScript anywhere in this crate. | A shell in Swift or Kotlin can call it |
| R7 | `angnative-services-core` — capability resolver, offline-sync queue (durable, conflict-aware, **no lost acknowledged operation**), crypto + secure storage, serialization, performance diagnostics. **Usable without Angular.** | Unit-tested; no Angular dependency in `Cargo.toml` |
| R8 | **Measure D8's number**: stripped + LTO static library size of `host-core + host-layout + host-view + host-engine` per platform | A measured figure, published. If it blows past 1 MB, that is the finding — not a reason to move the goalpost. |
| R9 | **View flattening + list recycling in Rust** — a component host with no style/prop/listener gets no native view; `na-list` recycles a fixed slot count | Matches §5.5 semantics; asserted by the suite |

> **R4 is the reason this plan is cheap.** Without a shared, mutation-tested suite, swapping the
> backend is a rewrite with no detector. With it, the Rust host is a drop-in that must pass a
> suite that already has teeth.

## 4. The keystone, stated plainly

There is exactly one artefact that makes the RN→Rust switch cheap instead of catastrophic:

> **A shared, mutation-tested conformance suite that the TypeScript fake backend and the Rust host
> both pass — with identical fixtures.**

Every other decision in this plan can be reversed later. That one cannot be un-built, and its
absence turns every backend change into a rewrite with no detector. Schedule it early, give it
teeth, and never let a backend land without it.

## 5. Verification pipeline, per commit (extends the spec's)

```
1. pnpm run check:toolchain      → Node >= 22.12, Angular == 22.2.5, TS == 6.0.3  (all three, checked)
2. pnpm run compile:fixtures      → ngc AOT succeeds; artefact shows inputs:/consts:
3. pnpm run build                → tsc -b exits 0, zero diagnostics
4. pnpm test                     → every suite green, including the conformance suite
5. node scripts/check-size-budget.mjs → <= 60 KB gzip; 0 B @angular/compiler, 0 B zone.js
6. cargo test --workspace        → Rust unit tests
7. cargo clippy --workspace --all-targets -- -D warnings
8. mutation check                → inject the original defect; confirm the gate fails with its exact numbers
9. cargo build --release --target <platform> && measure stripped+LTO size → <= 1 MB (D8's number)
```

## 6. Risks this plan carries, with the mitigation already written in

| Risk | Impact | Mitigation |
|---|---|---|
| The M1 tree is unrecoverable | High | P0.2 forces a decision before any code. Rebuild is possible — the TypeScript layer is ~10 tasks — but it must be a choice, not a drift. |
| Losing the RN native-module ecosystem | High | C4's first-party ABI is the guaranteed path; C5's matrix makes every gap explicit and written-down. This is the real price of leaving RN. |
| No device debugger (QuickJS-ng has no CDP) | Medium | D3 + D4 become load-bearing, not v0.2 nice-to-haves. Budget for them early. |
| Rust core blows the 1 MB budget | Medium | R8 measures it *before* platform shells are built. The number decides, not ambition (spec D8). |
| One engineer vs the breadth in §0 | High | Phases are ordered so a complete phase is shippable alone. Web + Android + iOS is the honest near-term surface; watch/TV/desktop follow. |
| A stale "merged" claim becomes a silent dependency | High | Every status in this plan is written as VERIFIED / MISSING / DIVERGED, never CLAIMED. |
