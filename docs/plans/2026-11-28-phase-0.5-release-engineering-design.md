# Phase 0.5 design — Release engineering + fresh-CI determinism

**Date:** 2026-11-28
**Status:** Approved by project owner (2026-11-28)
**Branch:** `feat/quickjs-bytecode-loader` @ `5ffe4f3` (pushed)
**Base for release:** `master` / `origin/master` @ `87e4eef`

## Context

`feat/quickjs-bytecode-loader` and `master` diverged at `aa8f2bc`: the feature
branch has 5 commits (host-clock easing, QuickJS bytecode v2 loader, three
review hardenings) and master has 28 commits (HMR + zero-copy JNI + ANB1,
Angular 22.3.0, Taffy 0.16.0, StubEngine, 13 CI/fresh-checkout fixes, Android
evidence/benchmarks). A final release tag on the current branch tip would
exclude those 28 master commits, so the owner chose: **no tag yet; reconcile
first**.

Master already fixed most fresh-checkout problems (`build:packages` in every
JS job, genuine `ngc` partial compilation, root `@angnative/*` links,
`compile:aot:marketpulse` + `bundle:marketpulse`, rxjs root declaration,
KVM/emulator boot sequencing). Our branch additionally fixes the
MarketPulse artifact gap in CI, the pending module-promise false success, and
the v2 bytecode container. The reconciliation must keep both sides' fixes.

Remote tags: only `v0.2.0`. `v0.3.0` is a local annotated tag at `9f90940`;
no `v0.4.0` release design or notes exist on master.

## Goals

1. Reconcile the feature branch with master without losing either side's work.
2. Prove that a genuinely fresh checkout reproduces the warm-worktree gates.
3. Cut a coherent, annotated `v0.4.0` release with evidence-backed notes.

## Non-goals

- iOS/Mac build, simulator or device runs (owner: Ammar).
- Any Phase 0.6 feature work.
- Performance/startup-speed or real-time guarantees.
- Rewriting the historical `v0.3.0` tag or its release notes.

## Plan

### Step 1 — Reconcile in an isolated worktree

Create a dedicated worktree from `5ffe4f3`, merge `master@87e4eef`, and resolve
conflicts in the seven overlapping files:

- `.github/workflows/ci.yml`
- `README.md`
- `crates/angnative-host-engine/src/lib.rs`
- `crates/angnative-runtime-bridge/src/lib.rs`
- `docs/SHOWCASE-TRACKER.md`
- `docs/UNSUPPORTED-FEATURES.md`
- `package.json`

Resolution rules: preserve master's `build:packages`, ngc wrappers, root
links, dependency bumps and CI fixes; preserve branch-only bytecode container
(`bytecode.rs`, `dump-bytecode.rs`, `quickjs.rs` pending-promise check), the
v2 magic in the ignored bridge test, and the MarketPulse CI ordering where
master does not already have it. `docs/UNSUPPORTED-FEATURES.md` on master still
calls bytecode loading "deferred" — update it to the implemented v2 state.

### Step 2 — Fresh-checkout determinism proof

In a clean clone/worktree (no reused `node_modules`, `dist/` or `target/`),
run and record exact outputs:

```powershell
pnpm install --frozen-lockfile
pnpm run build:packages
pnpm test
pnpm run check:toolchain
pnpm run compile:aot
pnpm run compile:aot:router
pnpm run compile:aot:forms
pnpm run compile:aot:i18n
pnpm run compile:aot:animations
pnpm run compile:aot:marketpulse
pnpm run bundle:quickjs
pnpm run bundle:forms
pnpm run bundle:framework
pnpm run bundle:marketpulse
pnpm run bundle:third-party
pnpm run bundle:bytecode
cargo test --workspace
cargo test -p angnative-runtime-bridge -- --ignored
pnpm run check:web-size
python scripts/check-ffi-declarations.py
```

Expected: all commands exit 0; regenerate the v2 bytecode artifact and record
its size/SHA-256 (the fingerprint includes target, so a fresh host may produce
a different hash from `4E637574…`). If the checkout is not truly fresh, say so
rather than claiming determinism.

### Step 3 — Release

- Write `docs/releases/v0.4.0.md` with verified gates and explicit scope limits.
- Refresh `STATUS.md`, `README.md`, `docs/SHOWCASE-TRACKER.md`,
  `docs/architecture/issue-register.md` and `docs/UNSUPPORTED-FEATURES.md` to
  the reconciled numbers; master's own trackers currently disagree (154/17,
  17 files/260 tests, 135/221 in README).
- Create annotated tag `v0.4.0` on the reconciled commit.
- Push branch and tag. Decide whether to also push `v0.3.0` so the remote tag
  history is contiguous; default is **yes**, because v0.3.0 release notes
  already exist and describe a stable snapshot.

## Evidence requirements

One new evidence doc, `docs/evidence/RELEASE-0.4.0-FRESH-CHECKOUT.md`, with
exact commands, exit codes, gate totals, artifact hashes, conflict-resolution
notes, and a clear "not verified" section (iOS/Mac, real GitHub Actions runner
if local replay only, device runs not repeated).

## Risks

- Dependency bumps mean all prior gate numbers are stale until rerun.
- Bytecode fingerprint is target-specific: artifacts must be regenerated on
  the target used for verification.
- Emulator CI job depends on `/dev/kvm`; a fresh non-KVM runner is out of scope.
- Merge conflicts in `runtime-bridge/src/lib.rs` and `host-engine/src/lib.rs`
  need review against both the HMR and bytecode call sites.
